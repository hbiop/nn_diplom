# NN Diplom — веб-приложение для обучения ML-моделей

> Портфолио-кейс Python/Django backend-разработчика для задач с загрузкой данных, обучением моделей и фоновыми процессами.

## О проекте

NN Diplom — Django-приложение, в котором пользователь может загрузить датасет в формате CSV/XLSX, выбрать модель и запустить обучение. Длительная операция выполняется отдельно от web-процесса через Celery, а состояние обучения доступно в интерфейсе и через JSON-эндпоинты.

Проект показывает практический подход к задачам, которые часто встречаются во фрилансе:

- личный кабинет с авторизацией;
- загрузка и просмотр табличных данных;
- ограничение доступа пользователя к собственным объектам;
- запуск долгой операции в фоне;
- отображение прогресса и истории эпох;
- хранение результатов обучения;
- запуск Django, PostgreSQL, Redis и Celery в Docker Compose.

Это учебный и портфолио-проект. Его можно использовать как основу для MVP или адаптировать под конкретный бизнес-процесс: классификацию заявок, обработку таблиц, внутренний кабинет или ML-сервис.

## Что можно реализовать для заказчика на этой основе

- Django-доработки: модели, формы, CRUD, личные кабинеты и права доступа;
- REST API и интеграции с внешними сервисами и webhook;
- импорт, проверку, очистку и экспорт CSV/XLSX;
- фоновые задачи через Celery и Redis;
- отдельный FastAPI-сервис для уже обученной ML-модели;
- Docker Compose для Django, PostgreSQL и Redis;
- небольшие frontend-доработки, подключённые к backend API.

Формат работы — небольшие задачи с понятным результатом: добавить endpoint, исправить авторизацию, подключить импорт Excel, автоматизировать обработку файла или вынести длительную операцию из HTTP-запроса.

## Основные сценарии

1. Пользователь входит в систему.
2. Загружает CSV- или XLSX-файл.
3. Просматривает структуру и первые строки датасета.
4. Создаёт сессию обучения и выбирает параметры модели.
5. Ставит обучение в очередь Celery.
6. Отслеживает статус, прогресс, логи и метрики по эпохам.
7. Использует сохранённые препроцессор и модель для дальнейшего предсказания.

### Примеры маршрутов

| Назначение | URL |
| --- | --- |
| Список датасетов | `/datasets/datasets/` |
| Загрузка датасета | `/datasets/upload/` |
| Сессии обучения | `/learning/sessions/` |
| Страница прогресса | `/learning/training/<session_id>/` |

Точные имена маршрутов и доступные действия определяются URL-конфигурацией приложения. Все рабочие сценарии требуют авторизации.

## Архитектура

```text
Browser
   |
   v
Django web  ---> PostgreSQL
   |
   +---------> Redis ---> Celery worker
                              |
                              v
                       Обучение модели
```

- **Django** отвечает за web-интерфейс, авторизацию, формы и бизнес-логику.
- **PostgreSQL** хранит пользователей, датасеты, модели и сессии обучения.
- **Redis** используется как брокер сообщений Celery.
- **Celery worker** выполняет обучение вне HTTP-запроса.
- **Docker Compose** поднимает сервисы и сохраняет данные в named volumes.

## Запуск через Docker Compose

### Требования

- Docker Desktop с поддержкой Compose;
- свободный порт `8000`.

### Установка

1. Склонируйте репозиторий и перейдите в его корень.
2. Создайте `.env` на основе `.env.example`.
3. Задайте уникальные значения `DJANGO_SECRET_KEY` и `POSTGRES_PASSWORD`. Для локального запуска остальные параметры должны соответствовать сервисам из `docker-compose.yml`.
4. Запустите приложение:

```bash
docker compose up --build
```

После запуска приложение доступно по адресу <http://localhost:8000>.

Создать администратора:

```bash
docker compose exec web python manage.py createsuperuser
```

Полезные команды:

```bash
# Остановить контейнеры, сохранив данные в volumes
docker compose down

# Посмотреть логи web и worker
docker compose logs -f web worker

# Остановить контейнеры и удалить volumes (удалит локальные данные)
docker compose down -v
```

При старте контейнер автоматически ждёт PostgreSQL, применяет миграции и собирает static-файлы.

## Текущий статус и ограничения

Проект готов демонстрировать архитектуру и как основа для дальнейшей разработки, но не заявляется как полностью production-ready решение. Перед коммерческим запуском нужно отдельно добавить или проверить:

- полноценный набор unit- и integration-тестов;
- API-документацию и стабильный публичный контракт;
- сохранение и использование Celery `task_id`, retries и idempotency;
- validation split и early stopping для обучения;
- строгую валидацию размера и содержания загружаемых файлов;
- production-настройки секретов, логирования, HTTPS и мониторинга;
- CI/CD и отдельную процедуру деплоя.

Такое разделение позволяет согласовать с заказчиком конкретный объём MVP, сроки и критерии приёмки, не обещая лишнего.

## Контакты и сотрудничество

Готов брать небольшие задачи по Python/Django backend, API-интеграциям, обработке CSV/XLSX, Celery/Redis и Docker. Для оценки задачи нужны: репозиторий или минимальный воспроизводимый пример, описание ожидаемого результата, тестовые данные, доступы к внешним сервисам и критерии приёмки.
