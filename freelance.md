# Стратегия выхода на фриланс

## Текущий профиль

Текущий набор навыков позволяет начинать брать небольшие коммерческие задачи уровня junior:

- Python;
- Django;
- базовый Django REST Framework;
- немного FastAPI;
- базовый React;
- PostgreSQL;
- Redis и Celery;
- Docker Compose;
- обработка CSV/XLSX через pandas;
- базовая ML-интеграция и API для моделей;
- авторизация, object-level permissions и защита пользовательских данных.

Главное преимущество — сочетание backend и базового frontend. Можно самостоятельно сделать рабочий MVP или связать существующий React-интерфейс с Django/FastAPI API.

## Важное ограничение

Не следует дословно записывать или выдавать скрытые внутренние рассуждения. Вместо этого полезно фиксировать проверяемые выводы:

- какие задачи подходят текущему уровню;
- почему они подходят;
- какие риски есть у заказа;
- какой результат нужно согласовать с заказчиком;
- какие навыки необходимо подтянуть.

## Рекомендуемое позиционирование

Основной вариант описания профиля:

> Python/Django backend-разработчик. Разрабатываю REST API, личные кабинеты и административные панели, подключаю PostgreSQL, Redis и Celery, интегрирую внешние API, работаю с Docker и обработкой CSV/XLSX. При необходимости подключаю React-интерфейс или FastAPI-сервис.

Не стоит позиционироваться слишком широко как специалист, который делает «любые сайты, приложения и нейросети». Лучше продавать понятный результат.

### Приоритетные направления

1. Django backend и REST API.
2. Доработка и исправление существующих Django-проектов.
3. Интеграции с внешними API и webhook.
4. Обработка CSV/XLSX и автоматизация.
5. Небольшие React-доработки для подключения к API.
6. FastAPI-сервисы для предсказаний и небольших микросервисов.
7. Docker Compose, Redis, Celery и развёртывание Python-приложений.
8. Telegram-боты после отдельной практики с `aiogram`.

## Какие заказы брать в начале

### 1. Небольшие Django-доработки

Подходящие задачи:

- добавить модель, форму и страницу;
- сделать CRUD;
- добавить фильтрацию, поиск и пагинацию;
- настроить регистрацию и вход;
- исправить logout или CSRF-проблему;
- закрыть доступ к чужим объектам;
- добавить роль или permission;
- подключить PostgreSQL;
- исправить миграции;
- добавить админскую страницу.

Почему это подходит: задачи близки к текущему проекту и позволяют быстро получить первый отзыв.

### 2. REST API на Django REST Framework

Подходящие задачи:

- создать serializer;
- добавить endpoint;
- сделать ViewSet или generic view;
- настроить pagination и filtering;
- добавить авторизацию;
- подключить React к существующему API;
- написать документацию Swagger/OpenAPI;
- исправить неверные HTTP-коды или обработку ошибок.

Пример объявления:

> Добавлю REST API к Django-проекту: serializers, permissions, фильтрация, пагинация, документация и тесты.

### 3. Интеграции с внешними API

Подходящие задачи:

- получить данные из внешнего API;
- отправить данные в CRM;
- обработать webhook;
- синхронизировать статусы заказов;
- подключить сервис уведомлений;
- связать Django с Telegram или платежным сервисом;
- сделать регулярную синхронизацию через Celery.

До начала работы нужно проверить документацию внешнего сервиса и наличие тестового доступа.

### 4. Обработка Excel и CSV

Подходящие задачи:

- импорт таблиц в базу данных;
- экспорт данных в Excel;
- очистка и объединение таблиц;
- удаление дубликатов;
- валидация строк;
- автоматическое формирование отчётов;
- массовое преобразование файлов;
- веб-страница для загрузки и обработки файла.

Полезный стек:

- `pandas`;
- `openpyxl`;
- `numpy`;
- Django или FastAPI;
- Celery для больших файлов.

Пример объявления:

> Автоматизирую обработку CSV/XLSX: загрузка, проверка, очистка, преобразование и выгрузка результата.

### 5. React-доработки в связке с backend

На первом этапе лучше брать не разработку большого frontend с нуля, а ограниченные задачи:

- подключить форму к API;
- добавить страницу списка;
- сделать таблицу с фильтрами;
- добавить состояние загрузки и ошибки;
- реализовать авторизацию;
- подключить polling статуса Celery-задачи;
- исправить запросы к backend;
- добавить простой компонент или модальное окно.

Не стоит сразу брать сложные заказы на полноценный React-продукт, если пока нет опыта с архитектурой frontend, состоянием и сборкой.

### 6. FastAPI и ML API

Подходящие задачи:

- создать `/health` endpoint;
- обернуть готовую модель в `/predict`;
- добавить Pydantic-валидацию;
- сделать batch prediction;
- загружать модель один раз при старте;
- добавить Docker-запуск;
- связать FastAPI с Django;
- добавить тесты через `TestClient`.

Лучше обещать интеграцию уже обученной модели, а не разработку любой нейросети с нуля.

Пример объявления:

> Оберну готовую ML-модель в FastAPI API с валидацией входных данных, `/predict`, Docker и документацией OpenAPI.

### 7. Docker и фоновые задачи

Подходящие задачи:

- написать Dockerfile;
- собрать Compose для Django, PostgreSQL и Redis;
- добавить Celery worker;
- исправить ошибку подключения контейнеров;
- настроить переменные окружения;
- подключить Gunicorn;
- исправить миграции при запуске;
- добавить healthcheck;
- настроить базовый деплой на VPS.

Сложный production-деплой, Kubernetes и высоконагруженная инфраструктура пока лучше не брать самостоятельно.

### 8. Исправление ошибок в существующих проектах

Это хороший формат первых заказов:

- исправить ошибку авторизации;
- найти проблему в Django ORM;
- исправить endpoint;
- разобраться с Docker Compose;
- исправить Celery-задачу;
- устранить ошибку импорта Excel;
- подключить существующий React к API.

Перед началом нужно договориться о диагностике: оплачивается ли исследование, какой объём кода доступен и что считается исправлением.

## Заказы, которые пока лучше не брать

С осторожностью относиться к задачам, где требуется:

- полностью разработать большой интернет-магазин в одиночку;
- сделать production-систему с высокой нагрузкой;
- гарантировать информационную безопасность без аудита;
- обучить сложную нейросеть на неизвестных данных;
- разработать мобильное приложение без соответствующего опыта;
- настроить Kubernetes-кластер;
- сделать высоконагруженные realtime-сервисы;
- поддерживать проект без доступа к репозиторию и логам;
- работать с неясным ТЗ и «неограниченными правками»;
- закончить чужой проект за подозрительно короткий срок;
- принимать оплату или доступы в небезопасной форме.

Отказ от неподходящего заказа защищает репутацию сильнее, чем неудачная попытка взяться за всё сразу.

## Как выбирать заказ

Перед откликом проверить:

1. Понятен ли ожидаемый результат.
2. Совпадает ли стек с уже имеющимися навыками.
3. Можно ли завершить задачу за несколько дней или одну-две недели.
4. Есть ли доступ к репозиторию, логам и тестовым данным.
5. Есть ли API-документация и тестовые ключи.
6. Кто отвечает за frontend, дизайн, сервер и домен.
7. Что входит в задачу, а что считается отдельной работой.
8. Как заказчик принимает результат.
9. Есть ли ограничения по срокам и бюджету.
10. Не требует ли заказчик работу до оплаты без понятных гарантий.

### Хороший первый заказ

- имеет одно-два понятных требования;
- использует знакомый стек;
- имеет тестовые данные;
- не требует архитектуры с нуля;
- имеет ограниченный объём правок;
- позволяет показать результат на скриншоте или в репозитории.

### Плохой первый заказ

- «сделать аналог известного сервиса»;
- «срочно исправить всё»;
- отсутствует репозиторий и ТЗ;
- заказчик не может описать критерии готовности;
- обещается большой объём за минимальный срок;
- требуется бесплатное тестовое задание, сопоставимое с полноценной работой.

## Что уточнять у заказчика

До начала работы письменно согласовать:

- точный список функций;
- используемый стек и версии;
- формат входных и выходных данных;
- дизайн или макеты;
- способ запуска;
- доступы и тестовые ключи;
- сроки;
- число раундов правок;
- формат передачи исходного кода;
- необходимость тестов и документации;
- критерии приёмки;
- стоимость дополнительных работ.

Хорошая формулировка границ:

> В стоимость входят endpoint загрузки, валидация CSV, сохранение результата и один раунд исправлений по согласованному сценарию. Изменение формата файла или добавление новой интеграции оценивается отдельно.

## Портфолио

Текущий проект можно оформить как основной кейс:

### Название

Платформа обучения и использования нейросетевых моделей.

### Что показать

- Django-приложение;
- авторизацию и изоляцию данных пользователей;
- загрузку CSV/XLSX;
- PostgreSQL;
- Docker Compose;
- Redis и Celery;
- прогресс и отмену обучения;
- безопасную сериализацию моделей;
- REST API;
- FastAPI prediction service;
- React-интерфейс, если он будет добавлен;
- тесты и CI.

### Какие материалы подготовить

- README с инструкцией запуска;
- архитектурную схему;
- несколько скриншотов;
- короткое видео работы;
- пример API-запросов;
- описание ограничений проекта;
- список тестов;
- ссылку на GitHub без секретов.

Важно описывать не только технологии, но и решённые проблемы:

- как закрыт доступ к чужим объектам;
- почему обучение вынесено в Celery;
- как предотвращается повторный запуск;
- как обрабатывается отмена;
- как защищается сериализация модели.

## План первых откликов

### Неделя 1

1. Оформить профиль и GitHub.
2. Подготовить описание текущего проекта.
3. Сделать три шаблона откликов:
   - Django/DRF;
   - обработка Excel/CSV;
   - API-интеграции.
4. Откликнуться на 5–10 небольших задач.
5. Не обещать функции, которых нет в портфолио.

### Неделя 2

1. Добавить в портфолио небольшой API-кейс.
2. Сделать пример FastAPI-сервиса.
3. Подготовить пример React-клиента для одного endpoint-а.
4. Откликаться на задачи с понятным результатом.
5. Записывать причины отказов и вопросы заказчиков.

### Неделя 3 и далее

1. Брать небольшие задачи, которые можно завершить качественно.
2. После каждого заказа обновлять портфолио.
3. Просить отзыв после приёмки.
4. Поднимать стоимость постепенно, когда появятся кейсы.
5. Отдельно учитывать время на переписку, диагностику и исправления.

## Итоговая стратегия

Оптимальное начальное позиционирование:

> Django/Python backend с REST API, интеграциями и обработкой данных; при необходимости — React, FastAPI, Celery и Docker.

Первые заказы лучше брать узкие и измеримые:

- endpoint;
- исправление авторизации;
- импорт Excel;
- API-интеграция;
- небольшая React-форма;
- FastAPI `/predict`;
- Docker Compose;
- Celery-задача.

Цель первых заказов — не максимальный чек, а качественно завершённые кейсы, отзывы и понимание реальной работы с требованиями заказчика.
